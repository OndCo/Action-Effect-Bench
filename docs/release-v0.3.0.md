# Real Maintainer Use and Full Manuscript

Bench prerelease `v0.3.0-draft.1`. Editorial date: 19 October 2026,
America/Toronto. This is a benchmark/evidence release, not a new core wire
version or an endorsed standard.

## What Is New

Real model-led maintenance tasks now exercise public GitHub sources through
Octokit and the official GitHub MCP server. A separately recorded follow-up
uses the same six intents after contract and evidence-visibility repairs.
Both runs retain all outcomes; they are internal exposed work, not twelve
independent tasks or an outside evaluation.

The full manuscript explains coupled effects, native/context/profile bindings,
ordered independent checking, conditional invariants and counterexamples,
current authority, bounded observation, durable occurrence handling, refusal
ownership, complete baselines, cost boundaries and the new field findings.
Its appendices map the protocol obligations to implementation and replay.

The new replay reconstructs captured model/tool control flow from retained
journals and reads verified historical Git blobs as data. Source-based quality
review remains distinct from these mechanical checks. Normalized release
metadata without a retained native envelope remains an explicit gap.

## Compatibility and Limits

Spec remains pinned to `a9b86f4b529a5e330c2a9bf1b8c4c259a7b36e40` and its
`v0.2.0-draft.1` release. Core wire remains `0.1.0-draft.1`. No old expected
case, report, source tag or release asset is replaced. The earlier nine-page
paper remains attached to the earlier Bench release.

New real-use work is read-only. It does not qualify the official MCP mutation
handler, autonomous write completion, hosted MCP authentication, complete
provider descendants, multi-host recovery or sustained customer production.
The older twelve actual comments are not reassigned to this new population.

No Studio, Hook, customer action, protected collaboration data, cloud resource
creation, new external invitation or formal manuscript submission is included.
The release carries no performance-superiority or independent-certification
claim. Replay requires no model/provider credentials; a new live model run
requires separately configured access and incurs costs.
