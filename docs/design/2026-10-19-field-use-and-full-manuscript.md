## Actual Work, Not Predetermined Comment Bodies

Use the deployed model to inspect real public release material through tools
and prepare useful maintainer reports. Tasks cover release-byte/source binding,
installation/reproduction instructions, versioned contract migration, native
MCP compatibility, evidence/recovery limits, and conformance documentation.
Freeze task goals, offered tool set, source snapshots, completion checks,
budgets and failure accounting before scored model runs. The model chooses its
read sequence and report content; the harness does not substitute a canned
answer. Do not give the model scoring answers as tool data.

Task correctness is distinct from effect mapping and current authorization.
An accurately mapped comment can contain a wrong technical conclusion. A model
may fail to finish even when every authorization decision is correct. Report
these separately, retain unfinished tasks, and do not revise labels after
seeing output to obtain a successful result.

Use a fixed set of read-only operations with explicit repository/ref/path
bounds. Read-only task tooling is a study capability boundary, not claimed
coverage by the existing comment-mutation profile. Report that coverage limit.
Model-visible repository content and tool descriptions are untrusted data, not
instructions. Do not expose arbitrary shell commands, URLs, secrets or write
tools outside the governed dispatcher.

Compare native SDK and official MCP task paths. Bind the proposed comment's

Record each scheduled task, every model request outcome, tool attempt and
provider operation, source/binary hashes, exact dependency versions, elapsed
time, provider-reported usage, cold/warm process boundaries and operator steps.
Record acquisition/setup failures as setup failures, not task failures or wins.
Do not publish tokens, private paths, raw authentication headers, encrypted
reasoning or unrequested private model reasoning.

Separate counts for model tasks, distinct intents, native calls, supported
mutation proposals, actual POSTs, confirmed effects, review/deny/processing
failure, duplicates and unknowns. Compare mapping against native capture and
authorization against separately specified current grants, not each other's

Stop further writes on an unexpected target, unbounded retry, missing journal,
source drift, exhausted budget, or unexplained provider outcome. A model safety
stop is retained and respected; do not switch APIs to evade it. No intentionally
exhausting GitHub quotas or load testing a shared public service.

## Full Manuscript

Preserve the old PDF and sources in the previous release. Replace the current
condensed presentation with a technically complete main manuscript, plus a
readable companion Markdown version. Expected length is driven by material,
approximately 25-35 pages including appendices, not a padded page target.
