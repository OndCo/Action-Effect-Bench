\begin{abstract}
Tool interfaces describe calls, while authorization concerns consequences under
particular implementations, arguments, principals, and environments. Existing
MCP annotations, rich authorization requests, decision APIs, and policy engines
already provide important parts of this contract. We propose a bounded empirical
protocol for testing whether an implementation- and context-qualified effect
interchange preserves supported meaning across integrations at a justified cost.
The protocol separates conformance, native-input mapping, authorization on
independently specified reference effects, integrated admission, observed task
outcomes, and complete cost. A bounded GitHub issue-comment pilot was executed
using MCP and SDK lanes, with a complete structured adapter and the same real
OPA policy as the main baseline. Deliberately lossy mapping is an ablation,
not a competitive baseline. Mapping errors masked by correct-looking denials,
semantic unknowns, processing failures, legitimate work withheld, and ambiguous
delivery remain separate outcomes. Both complete strategies matched all 108
native lane instances from 55 authored cases in 22 intent groups, and all 52
eligible decisions. A controlled live run matched 32 planned outcome checks
and created 12 comments, including four recovered after deliberately discarded
acknowledgments. The protocol's accepted-input offline median cost was 3.97\%
higher. These same-project results support bounded feasibility, not added
safety, performance superiority, independent validation, production readiness,
or a new subset-inclusion theorem.
\end{abstract}

\section{Problem and Proposed Contribution}

A tool name does not identify every consequence, and a worrying string does
not establish a harmful occurrence. An interchange must preserve coupled
operation, resource, destination, data, quantity, applicability, and uncertainty
without confusing a declaration with authority. This is not an empty space:
MCP describes annotations as hints~\cite{mcp}; AuthZEN supplies authorization
exchange~\cite{authzen}; OAuth RAR already supports detailed permission
objects~\cite{rar}; and OPA/Cedar evaluate structured facts~\cite{opa-api,opa-lang,
cedar-auth,cedar-validation}.

The proposed contribution is a testable contract plus a factorized experiment
and failure/custody procedure. Its value would be evidence that different
integrations preserve the same supported semantics, expose the same limits,
and permit useful controlled work at an acceptable cost. More fields, another
serialization, or agreement between same-project implementations is not enough.
A complete baseline may be equally correct or cheaper. Such a finding must be
retained, not reframed as added safety.

\section{Semantic and Trust Model}

An effect is a coupled tuple of category, operation, resource, destination,
data class, quantities, and modality. A description adds the effective profile,
mapping revision, invocation/implementation/context bindings, evidence, coverage,
and explicit unresolved facts. It does not redefine the current grant or the
execution occurrence. Known, none, and unknown remain distinct. Fields from
different alternatives cannot be recombined into an unasserted permission.

\subsection{Evidence Is Not Permission}

Description processing establishes supported interpretation; a checker can
establish only the particular claim covered by its evidence and assumptions.
Authorization uses separately authenticated facts and current policy. A final
gate controls dispatch, while a provider observation covers an actual occurrence.
None of these states implies all the others. Description acceptance remains
\code{authority: not_evaluated}.

Missing required evidence withholds the affected execution but is not a
correctly recognized semantic block. An applicable trusted denial survives
unrelated uncertainty. Human review can authorize a deliberately limited scope;
it cannot make an invalid proof valid. Acceptance of a partial direct-effect
profile for one owned test resource cannot silently downgrade another policy's
requirement for complete descendant coverage.

\subsection{Ordinary Obligations, Not a New Theorem}

If a sound checker establishes $E\subseteq U$, authority permits $U$, and
execution stays mediated under the same assumptions, covered admitted effects
respect that authority. For a policy expressible as an allowed set $B$, the
implication from $E\subseteq U$ and $U\subseteq B$ to $E\subseteq B$ is ordinary
subset inclusion, not a new theorem. Establishing the premises is the hard part.
History, aggregate budgets, and temporal constraints are not generally
independent per-tuple membership tests. An observed trace also does not establish
a complete upper bound on possible behavior.

Relevant faults include body/context/implementation drift, stale evidence,
untrusted declarations, tuple recombination, changed authority, duplicate
occurrences, and uncertain delivery. Arbitrary hidden SaaS behavior, covert
channels, and unmediated effects outside the declared universe are not covered
by the finite pilot.

\section{Relation to Existing Interfaces}

\paragraph{MCP.}
The selected \code{2025-11-25} schema includes read-only, destructive,
idempotence, and open-world hints, with an explicit warning against trusting
annotations from untrusted servers~\cite{mcp}. It is not asserted to be the
latest revision or the protocol actually negotiated in a run. A supported
effect extension needs its own agreed semantics; there is no claim of an
upstream-standard Action-Effect field. A capable MCP integration can already
use a context-aware structured adapter, so hints-only comparison is insufficient.

\paragraph{AuthZEN and RAR.}
AuthZEN Authorization API 1.0 is Final, published 11 January 2026, and provides
subject/action/resource/context decision exchange~\cite{authzen}. Its successful
decision is boolean with optional context. Review, unsupported semantics, and
processing failure need explicit application-level mappings, not invented
boolean values or automatic correctness credit for a failed PDP call.

RAR's structured \code{authorization_details} and separate objects already
preserve distinct permission combinations; coupling is not novel merely because
this draft also requires it. RFC 9396 section 6.1 explains that arbitrary details
lack a universal comparison operation independent of type semantics~\cite{rar}.
Requested details, granted details, and described effects are different.
Token privilege restriction, audience checks, and actual resource authorization
remain necessary~\cite{oauth-bcp}. Reusable evidence does not cache permission.

\paragraph{OPA and Cedar.}
OPA accepts complete structured input. Its Data API can return HTTP 200 without
a \code{result} for an undefined document, while built-in errors ordinarily
evaluate to undefined unless the selected strict-error mechanism changes that
behavior~\cite{opa-api,opa-lang}. The required total-decision wrapper must
validate outputs and declare its error configuration identically across arms.

Cedar provides principal/action/resource/context requests, entities, policies,
and schema validation. Its documented default-deny, forbid-overrides-permit,
and skip-on-error semantics return diagnostics; an error in one policy can
coexist with an Allow from another~\cite{cedar-auth,cedar-validation}. That is
not automatically a Cedar defect. A stricter wrapper or review route must be
explicit and symmetric. Policy validation does not authenticate facts. Cedar
is a future comparator, not an executed lane of the current OPA pilot.

\paragraph{Provenance, bytes, and provider behavior.}
PROV-DM structures provenance but does not establish factual truth~\cite{prov}.
JCS defines canonical JSON, not authority or semantic correctness~\cite{jcs}.
The finite consumer's numerical subset must not be presented as full
binary64/JCS support. GitHub documents notification effects and secondary rate
limiting for comment creation~\cite{github-comments}. Recipients, delivery,
webhooks, and other descendants remain unresolved under the partial profile.
Reading a comment does not establish their absence. HTTP retry semantics
likewise do not make an uncertain create safe to repeat~\cite{http}; a local
marker or MCP hint is not a provider idempotency key.

This is a focused compatibility review, not a complete scholarly novelty review
of effect systems, abstract interpretation, capabilities, information-flow
control, or agent governance. No superiority over an unintegrated system follows.

\section{Falsifiable Questions and Experimental Design}

\code{PROTOCOL.md} governs the study; this paper does not silently change its
corpora, labels, scoring, or independence requirements.

\begin{enumerate}
\item \textbf{Meaning preservation:} do both arms match reference coupled
effects, binding state, and uncertainty across equivalent intents? Baseline
parity supplies no added mapping benefit; extra loss or unsupported outcomes
count against the proposed interchange.
\item \textbf{Diagnostic value:} can separate mapping, reference-input
authorization, and integrated scores reveal policy-masked mapping defects?
Report their joint correctness cells, with additional explicit failure cells.
A complete baseline may expose the same distinctions.
\item \textbf{Unknowns and freshness:} do prewritten drift, authority-change,
capability, and delivery cases preserve required limits? Fabricated known facts,
stale acceptance, error-as-review, and permission reuse contradict the contract.
\item \textbf{Cost and utility:} does any demonstrated portability or protection
benefit justify complete cost, withheld work, intervention, and recovery?
Negative findings and a better baseline remain valid outcomes.
\end{enumerate}

The base intent is the sampling unit; variants, repeats, languages, and lanes
are not extra independent cases. This is an author-designed convenience pilot,
not a customer-workflow population sample. Competence and tuning budgets must
be matched in public development. An OPA evaluator cannot define the expected
answers and then receive independent correctness credit for matching itself.
Pure authorization uses separately authored reference effects and decisions.

\paragraph{Authoring and independence.}
Implementation, separate case authoring, and review were AI-assisted within one
project. Literal references were authored without candidate-output inspection;
implementation proceeded in parallel from the agreed public interface. The
corrected custody record describes withholding cases until a
\emph{pre-execution/pre-result} freeze, not a pre-implementation freeze.
Subsequent failures became exposed regressions. The editorial audit checks
retained reports after execution, not independent reference authorship. No
external evaluation or protected external cohort occurred.

The selected official OpenAPI commit is
\code{755ee33b4a81d51f6f07a902cce26cbec3b822f2}~\cite{github-openapi}.
The pinned excerpt retains its MIT notice and supplies structural examples and
notification wording, not independent governance labels. Official commit
identity and local extraction hashes remain separate records. After a learned
failure, that family becomes exposed development;
hiding or hashing it does not restore unseen status.

Protected external evaluation additionally requires independently authored
inputs and outcomes, separate sealed access, actual custodians, independent
disputed-score governance, and disclosed conflicts. System exposure is not
developer access. Hosted-provider logging can undermine secrecy and must be
documented. Two languages, repositories, or AI-assisted sessions do not establish
independent laboratories. Active protected traces and labels stay sealed until
retirement and rights review.

\section{Metrics and Analysis}

Primary rates use their full frozen scheduled populations, including unsupported,
missing, and failed output. Successful-only rates are supplementary. Pure
malformed-wire cases occupy a predeclared separate track; no favorable post hoc
exclusion is allowed.

\paragraph{Mapping and uncertainty.}
Report exact semantic match, coupled-tuple and per-field loss, correct scope,
modality, and bindings, together with coverage and reference ambiguity. For
reference-unknown slots, report correct unknown retention and unjustified
known/none assertions; for reference-known slots, report avoidable unknowns.
Missing output earns no unknown-retention credit. Capability/processing checks
may correctly return unsupported without establishing successful effect mapping.

\paragraph{Decisions and admission.}
Let $A$, $B$, and $R$ be the preassigned expected-allow, expected-block, and
expected-review populations. Table~\ref{tab:metrics} defines rates, not results.
Retain full confusion tables including non-decisions for pure authorization
and integrated admission. Record the gate and actual dispatch independently.

\paragraph{Failure, completion, and recovery.}
Separate invalid input/configuration/output, unsupported semantics, untrusted
evidence, timeout, crash, missing output, and policy/provider/observer failures.
Retain every attempt and link each permitted rerun; do not select the best run.
Intentional non-dispatch is not attempted delivery. Provider outcomes can be
confirmed, partial, unknown, or conflicting. Unknown-delivery rates use all
attempted occurrences, also showing counts against scheduled work.

Original task completion uses all scheduled legitimate tasks; withholding,
timeout, abandonment, and missing completion are non-completions. Report
forbidden effects, duplicates, retained reservations, reconciliation, and human
burden. Joint verified useful-and-safe completion needs the original goal,
no forbidden effect in the declared universe/window, and sufficient observation.
Unknown coverage cannot qualify. Direct-comment-only success must be called
scoped verified completion, not safety of every descendant. Separate clean and
challenged workloads and label conservative sensitivity bounds as bounds.

\paragraph{Complete cost and inference.}
Retain raw monotonic timings for preparation, parsing, mapping, serialization,
validation, evidence checking, invalidation, authorization, final recheck,
reservation, transport, provider response, readback, and reconciliation.
Include end-to-end boundaries, cold/warm state, startup, offered/rejected work,
input size, load, resources, network, provider calls, and measured human or
monetary cost. Do not sum overlapping timers or turn unmeasured cost into zero.

Use paired intent-level comparisons and predeclared family weighting, clustering
variants and repeats. Small convenience samples warrant descriptive findings,
not population coverage or unsupported tail-SLA claims. Report sample support
for percentiles. Zero observed failures is not zero risk; correlated variants
do not justify an independent-trial bound. Preserved utility or review burden
needs justified preregistered non-inferiority criteria, not a nonsignificant
difference. Publish negative results and analysis deviations.

\section{Current Artifacts and Limitations}

The legacy finite refund profile remains separate; its original-corpus rerun
matched 102/102 expected outputs per consumer with no adapter faults. Released
opt-in \code{offline-consumer-v1.1} clarifies startup and compound-error
precedence without rewriting frozen v1. These are not new runtime workloads.

\href{https://github.com/OndCo/Action-Effect-Bench/actions/runs/39199258635}{Linux/macOS CI}
succeeded at the measured commit. Reported totals are 64 Spec JavaScript,
11 legacy Bench JavaScript, 115 Spec Python, 333 runtime JavaScript, and
50 runtime Python methods: 573 methods, not benchmark cases.

The scope remains one synthetic public operation, not arbitrary tools,
autonomous-model behavior, or customer workflows. Notifications, recipients,
delivery, webhooks, and other descendants stay unknown. The host, configured
principal/class, policy files, provider adapter, and same-host ledger are
trusted. The bridge identity is declared, not attested SaaS code.

Snapshots across awaits and exact response/readback ID binding close specific
reviewed defects, not every concurrency or revocation race. Local policy and
remote mutation remain non-atomic. ID-less recovery is conditional on complete
preflight and a dedicated single writer; new exact content is not execution
attribution. A same-account concurrent writer remains outside that guarantee.
Hashes and replay do not authenticate an operator or establish historical fsync.

Internal review reports eight gate regressions corrected before the measured
source, involving stale/edited content, ID binding, mutable configuration, and
policy freshness. This is development history, not another cohort. Shared
contracts and policy permit correlated mistakes. External independently
authored evaluations remain zero. Full descendant coverage, independent
implementations, realistic load, operational effort, and deployment readiness
remain unestablished.

\subsection{Retained Failure and Replay}

The first failed offline report is retained. Its scorer reported 52 apparent
masked errors per strategy from null-prototype versus ordinary-object
comparison. A JSON-value audit finds 108 exact protocol and 100 exact structured
mappings; eight structured numeric/Unicode error-classification mismatches
remain. These are not 52 real policy-masked defects. All 216 input/context/
policy and expected records are unchanged in the final report. Repairs changed
code and scoring, not labels. The complete initial executable tree was not
archived; this is retained evidence, not exact old-source reproduction.

Offline replay passed 216 strategy rows plus 52 reference/diagnostic records.
Live replay passed 32 rows and matched all 12 unique comments using anonymous
GETs at its recorded check time. The attempt journal has one begin, 32 scheduled,
32 result, and one end record consistent with the live report. Replay verifies
recorded consistency, calculations, and current content, not operator honesty,
historical latency, fsync, or complete causality. Later unavailable, changed, or
rate-limited content cannot be treated as a match. The full artifact map is in
\path{measurement-contract.md}.

\section{Adoption, Rights, and Publication Boundary}

Adoption is staged and interface-only: bounded offline implementation,
non-dispatching comparison, then a separately authorized owned-resource test.
No OSuite endpoint, account, module, purchase, or code is required. The adoption
quickstart documents implemented installation, offline, replay, and authorized-live
interfaces with automatic read-only lost-ACK recovery. Supplied unit tests and
source inspection do not establish completed measurements, customer deployment
readiness, or a reason to remove existing controls.

The public RFC asks for concrete tuple-loss, drift, unknown/failure, freshness,
recovery, and fair-baseline tests. Protected inputs and outcomes must not be

\section{Conclusion}

Action-Effect is useful only if its interchange preserves supported meaning,
exposes limits, and enables controlled useful work at a justified cost relative
to competent existing integrations. The proposed factorization makes masking,
failures, and parity visible. The completed bounded study found equal mapping
and authorization checks, equal planned live outcomes, and higher accepted-input
offline median cost for the protocol. It supplies an inspectable interchange
and empirical method, not demonstrated superiority over a complete structured
adapter. Independent evaluation and broader operational evidence remain open.
